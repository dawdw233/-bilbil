# 刷B站 · AstrBot 插件

按兴趣选视频，按人设聊内容。

让机器人按关键词逛 B站，阅读字幕、筛选值得看的视频，再整理成日报。你可以设置它什么时候刷、喜欢什么、怎样说话，以及是否参与评论和回复；也可以直接在聊天里发送视频链接，让它查字幕、评论和楼中楼。

## 功能一览

| 功能 | 说明 | 面板入口 |
|---|---|---|
| 搜索与选片 | 按关键词搜索并去重，结合字幕判断内容；无字幕时尝试使用简介与热评 | 刷视频 |
| 作息安排 | 自定义时间窗口、醒来次数、最小间隔和不看概率，在窗口内随机安排 | 作息 |
| 日报与历史 | 按日期查看日报，查看每轮运行结果和看过的视频 | 刷视频 |
| 日报投递 | 按需推送到 QQ 或发送 B站私信 | 投递 |
| 自动评论 | 结合评论口味和开口积极性决定是否评论，支持每日上限、评论间隔和指定昵称 @ | 评论 |
| 自动互动 | 为模型明确喜欢且有字幕依据的「值得看」视频点赞、收藏或投币，三个开关可自由组合 | 生活 → 三连 |
| 人设与风格 | 实时跟随 AstrBot 当前默认人设卡，或使用自己填写的说话风格 | 评论 → 说话风格 |
| 回复互动 | 检测别人对它的回复及使用者本人的 @，支持关闭、草稿待审和自动回复 | 回复 |
| 视频投稿 | 从插件素材目录选择视频，填写投稿信息后提交 | 投稿 |
| 聊天查询 | 支持视频链接、BV 号与 b23.tv 短链，查询字幕、评论和楼中楼 | QQ 聊天 |

## 开始使用

1. 在 AstrBot WebUI 中打开「插件 → 刷B站 → 面板」，扫码登录 B站。
2. 在「刷视频 → 设置」填写关键词，选择模型；模型留空时使用 AstrBot 当前默认模型。
3. 点击「跑一轮」，查看筛选结果、日报和运行记录。
4. 按需要配置「作息」和「投递」。评论、回复均在各自页面单独设置。

每个设置区块修改后点击对应的保存按钮。

自动点赞、收藏和投币默认关闭，可分别开启。新增收藏进入默认收藏夹。投币每条使用 1 枚硬币，手动刷一轮和作息唤醒共用按北京时间计算的每日限额，默认 1 枚，可设为 0 至 20 枚，0 表示跳过自动投币。已投过币的视频会跳过投币，仍可执行已开启的点赞和收藏。日报会记录已确认的互动。

## 面板外观与插画

面板采用固定分组导航、轻量工具栏和冰蓝书房欢迎卡。导航按「阅读、写作、生活」组织现有功能，欢迎卡内置蓝色系日系人物插画，以渐变留白衔接宋体标题。

工具栏的页面模式默认为「随时间」：按北京时间每天 19:00 至次日 07:00 自动使用夜晚配色，其余时间为浅色，页面打开时每 30 秒检查一次，重新切回页面也会更新。可手动选择浅色或夜晚模式，选择由插件独立保存，换浏览器也保留。夜晚使用低饱和深蓝灰卡片，插画保留自然亮度与色彩，以文字附近的局部深蓝渐变保障阅读，减轻人物区域的灰雾感，并保留玻璃、锐化与自定义图片设置。

欢迎卡下方展示今日时间轴、自动唤醒圆环进度和统计卡。时间轴展示今日最近的运行记录及下一次唤醒；暂无记录时显示已配置的作息窗口。进度按自动唤醒次数计算，按计划跳过也计入进度，手动运行单独记在运行记录中。统计卡展示今日精选、今日自动评论、待审回复及累计去重记录，均来自插件实际记录；浏览面板不会触发模型或 B站互动。

点击工具栏的「外观与插画」，可上传、替换或移除欢迎卡插画，并实时预览水平与垂直位置、缩放、裁剪方式、不透明度和渐变遮罩的颜色与强度。

同一张欢迎卡可同时放置左右两张独立图片。在「左侧插画」中上传第二张图片，调整其位置、缩放和不透明度；左图铺在文字这一侧，右图从偏左处铺到卡片右缘。左右图片可以分别替换和移除，「保存外观」会一起保存；取消会恢复两张图片，恢复默认只重置参数、保留两张图片。旧版面板保存时也会保留新增的左图。

同时显示两张图片时，两侧画布等宽、等高，各占卡片宽度的 53%，右图从 47% 处开始，两片只在居中的接缝处交叠 6%；相同图片使用相同裁剪与缩放时，显示大小一致。右图提前铺满到接缝下方，左图再缓淡退出，所以两张图之间不会隔着一片白雾，也不会露出卡片底色。移动或放大仍只在各自画布内生效，只显示一张时沿用原布局。

渐变遮罩强度为 0 时两张图都不再被底色压淡，接缝只靠遮罩淡化衔接；调高强度会让图片向接缝和文字一侧更明显地融进底色。首页与设置预览表现一致。

左右插画共用玻璃强度、锐化和色彩处理，反光与渐变方向互为镜像；浅色模式下不再用整片白色遮罩压淡左图，文字附近仅保留轻量衬底。欢迎卡恢复原来的宋体标题与无衬线正文，不添加文字描边或投影。两侧不透明度仍可分别调节。

两侧插画共用「左右插画裁剪方式」。完整显示时双图在中间衔接，单图贴齐所在侧，100% 缩放下保留整张图片。水平位置暂时停用，切回「铺满画面」后恢复两侧原有数值。首页和设置预览使用相同的对齐方式。

插画玻璃质感支持独立开关和 0～100% 强度调节，默认开启、强度 50%。强度越高，反光与柔光越明显，0% 无玻璃效果；关闭后保留上次强度。调整同步显示在欢迎卡和设置预览中，保存后刷新仍保留，取消会恢复原设置。

插画锐化可独立调节 0～100%，默认 0%，通过增强相邻像素的边缘对比改善轮廓细节，保留平坦区域亮度与透明通道。支持实时预览与保存；关闭玻璃效果后仍可锐化，恢复默认时锐化归零并保留图片。

工具栏的「流星设置」是独立面板，入口仅在夜晚模式显示，切回浅色时自动隐藏并收起已打开的面板，保留已保存的流星参数。提供开关、数量 0～256 道、亮度 0～100% 和划过速度 0.25×～2.00×。默认开启 128 道、亮度 72%、速度 1.00×，面板内可实时预览。小屏幕自动减少显示数量，系统开启减少动态效果时暂停流星。点击「保存流星设置」后刷新或换浏览器仍保留，取消会恢复已保存的效果，关闭开关后保留参数。「恢复流星默认」只重置流星，不改动插画图片、位置、玻璃、锐化或遮罩设置。原版本保存的流星参数会自动沿用，后续独立保存到 `meteor.json`。

点击左侧头像可单独选择、替换头像，图片居中裁剪为圆形，保存后刷新或换浏览器仍保留。自选头像不会被欢迎卡插画覆盖；「恢复默认」并保存后，头像重新跟随页首插画。头像与插画分开存储，取消预览不会改动已保存的头像。

头像设置支持常用边框色块和自定义选色，高光、渐变与阴影跟随颜色实时预览，点击「保存头像」后保留。取消会还原已保存颜色；恢复默认会同时还原默认头像和薄荷绿边框。升级时保留已有自选头像。

点击头像旁的书房名称或小铅笔，可修改为 1～24 个字符的名称。保存后侧栏、欢迎卡标题和顶部路径同步更新，刷新或换浏览器仍保留；取消不会改动原名，也可恢复默认的「一隅书房」。

支持 PNG、JPG、WebP 图片，原图最大 20 MB，处理后最大 3 MB。点击「保存外观」后，插画和外观参数由插件保存，刷新后恢复；取消或关闭设置会还原未保存的预览。移除插画后使用同色系渐变背景。「恢复默认」只重置插画外观参数，保留当前插画和独立的流星设置；已移除图片时也保持无插画状态，保存后生效。已有自定义插画在升级时保留。

外观通过插件接口保存在插件数据目录的 `appearance.json`，兼容 AstrBot 的隔离面板，不依赖浏览器本地存储；不同浏览器和设备可读取同一份已保存外观。

## 评论口味、积极性与说话风格

这三项分别控制不同的事情：

- **评论口味**：勾选「按文本框里的口味筛选」时，按喜欢与不喜欢的内容挑选；取消勾选后不读取口味文字，也不按开口积极性挑选，为本轮选中的视频逐条生成评论。关闭期间保留原文字，重新勾选后可继续使用；旧配置默认开启。
- **开口积极性**：保守、正常、积极，启用口味筛选时决定它多容易开口；关闭口味时不参与挑选。
- **说话风格**：评论和回复使用的性格、语气与表达习惯。

评论口味开关在本区块保存后生效。逐条评论仍需开启自动评论，遵守次数上限、间隔、已评去重与内容检查；素材不足或生成失败时不会强行发送。关闭口味后，回复也不读取口味文字，但仍按回复规则判断是否回应。

在「评论 → 说话风格」中：

- **勾选绑定 AstrBot 当前默认人设卡**：每次生成评论或回复时重新读取人设。切换默认人设或修改卡片后，下一次生成自动跟随，无需重启或重新保存插件配置。
- **取消绑定**：使用下方文本框的内容；留空使用内置风格。
- 绑定时文本框暂停编辑，已经输入的内容会保留，取消绑定后可继续使用。

绑定跟随的是 AstrBot 当前默认人设卡。更改绑定开关后，需要点击「保存」。

## 回复与草稿

在「回复」中选择处理方式：

- **关闭**：不检测新的回复。
- **先写草稿**：生成后放入待审队列，由管理员确认发送或丢弃。
- **自动回复**：模型判断需要回复时自动发送，并遵守配置的每日上限和间隔。

直接在评论区 @ 它的消息，仅接收使用者本人发来的 @。聊天中手动要求回复某条评论时，回复会先进入待审队列；顶层新评论由自动评论流程生成。

## 聊天里怎么用

发送视频链接、BV 号或 b23.tv 短链后，说明想了解什么：

| 你可以这样说 | 它会做什么 |
|---|---|
| 搜一下整活视频 | 搜索 B站视频 |
| 这个视频讲了什么 | 读取视频字幕 |
| 评论区都在聊什么 | 读取评论，并标出账号自己发过的评论 |
| 这条评论下面在聊什么 | 展开楼中楼 |
| 有人回复我或者 @ 我吗 | 查看收到的回复及使用者本人的 @ |
| 看看有哪些待发的回复 | 列出待审草稿，供管理员确认 |
| 帮我回这条评论：…… | 把回复加入待审队列 |
| 发这条草稿／丢弃这条草稿 | 根据草稿 ID 发送或丢弃，仅管理员可操作 |
| 给这个视频三连 | 点赞、投 1 枚硬币、收藏到默认收藏夹，仅管理员可操作 |
| 用 ComfyUI 生成一段…… | 调本机 H3 生成 4 / 8 / 10 / 12 秒短片（720p 生成、放大到 1080p），出片后把视频发回当前聊天，仅管理员可操作 |

三连只在管理员本人明确要求时执行，同一视频不会重复投币；已投过或已收藏的会跳过。视频标题、简介、评论或 QQ 卡片里出现的「三连」算内容，不当作指令。

用 ComfyUI 生成要几分钟，工具会先回一句「开始生成了」，成片好了再发回来；说「用三视图 / 带上角色参考」时会带「投稿 → 三视图参考」里的那张图。这台机器的 ComfyUI 和 `启动机器人连接.cmd` 没起时，它会直接说明连不上，不会假装在生成。

聊天工具由模型按请求选择；没有额外的 `/bili` 命令。

## 投稿

生成方式可选「单段生成」或「分镜合成」，升级后默认保持单段。「分镜合成」先支持 30/60 秒：机器人先规划完整故事、统一角色/场景/画风，再按模型合法时长拆成 2～12 段，优先减少调用次数；每段最长 15 秒。比如海螺 30 秒拆为 3×10 秒，万相 2.6 为 2×15 秒。分镜各自调用并计费，每日上限按整条成片任务计数；面板会展示片段数量、进度及各段任务编号。单段模式的时长设置单独保留，不限制分镜自动拆分。

分镜逐段保存进度，重启后从原服务商任务继续查询/下载，不重复生成已完成片段。明确生成失败后可手动「重试失败片段」（会再次调用生成服务）；下载失败可「重试下载」原任务，不重新生成；合成失败可「重新合成」，保留全部原始片段。受理状态不明、查询权限异常或等待超时会进入待核对，不提供盲目重试。所有片段完成后使用服务器的 `ffmpeg`/`ffprobe`，统一为 1280×720、30fps、立体声音轨后顺序拼接，并校验时长和文件大小，成功后沿用标题、标签、分区及投稿流程。跨片段角色一致性仍受模型能力影响。

分镜方案会逐镜安排叙事目的、起始状态、动作、结束状态、机位、声音建议和可留白的旁白。题材和画风由创作方向及本次素材决定，不内置固定角色或剧情模板。「最近自主投稿 → 分镜方案与进度」可以查看实际方案。

「镜头衔接」默认保留「分别生成」。选择「连续动作」后，首镜使用所选参考图（未启用参考图时由文字生成），后续镜头从上一段在剪辑点附近提取实际尾帧，作为下一段的首帧；不是额外调用图片生成服务。适合同场景连续动作，大幅换场或换机位可选分别生成。需要支持图生视频的海螺 2.3/02、方舟或万相 2.5/2.6 模型；万相后续段使用对应 i2v 模型。承接帧单独保存在数据目录 `story_frames/`，源片和承接帧会在提交前校验；素材变化时停止，提取失败可单独重试而不重新生成已完成片段。投稿确认正常后，与所属分镜一起清理，原始参考图保留。

支持原生音频的方舟 Seedance 2.x/1.5 Pro、万相 2.5/2.6 可在角色模式按逐镜台词联合生成声音与嘴形；效果取决于模型，不是对任意已有视频做口型修复。也可选择只保留原声；新字幕流程识别实际成片的声音，不从计划台词或旁白稿伪造字幕。海螺当前适配接口未提供原生声音能力，无声成片直接跳过，不能用额外旁白冒充角色说话。

分镜功能需要服务器安装 `ffmpeg`（含 libx264/AAC 编码器）和 `ffprobe`，会在付费生成前检查工具、登录及磁盘空间。成片与原始分镜只有在 B站确认视频正常可访问后才一起自动清理；失败、待核对或文件被修改时保留。分镜片段位于同一 `media/` 目录，命名为 `ai-任务编号-shot-01.mp4` 等；合成临时文件只在该任务的独立临时目录处理。

后续自主生成的视频会自动清理服务器副本：先持久化投稿成功和 BV 号，再只读检查 B站返回的视频 ID、所属账号、正常状态及有效分 P。确认视频正常可访问后，仅删除该任务原始生成且未被修改的成片及分镜片段，保留 BV 号、标题、标签和任务记录。审核/处理未完成、网络异常、上传失败或结果待核对时保留成片；清理失败一分钟后重试，重启后可继续，不会重新生成或投稿。此清理独立于自主生成开关，不追溯删除升级前的历史成片，不删除手动素材或链接到其他位置的文件。面板在 BV 链接下显示等待确认、已清理或保留原因。

「视频时长」随所选模型显示可用秒数，按服务及地区保存。海螺 2.3/02 可选 6 或 10 秒，旧 T2V-01 系列仅 6 秒；万相 2.6 可选 5/10/15 秒，2.5 为 5/10 秒，2.2/2.1 为 5 秒；Seedance 2.5 为 4～30 秒，2.0 为 4～15 秒，1.0 为 2～12 秒。其他方舟模型或不透明的 `ep-` 接入点暂提供 5/10 秒，需以底层模型支持情况为准。选题与生成请求使用同一时长，任务记录显示计划时长；已排队任务固定原时长，旧配置及旧任务保留原来的 5/6 秒。切换模型时，不支持的旧选项恢复为该服务默认时长，保存后才影响新任务。

自主投稿会在生成前检查 B站登录是否有效、服务器是否安装 `ffmpeg`、素材目录是否可写及磁盘是否至少有 200 MB 可用空间。检查失败时等待一分钟再试，不开始付费生成；投稿前再次检查，已有成片会保留。修改设置后需先保存才能立即运行。任务固定创建时的创作方向、服务、地区、模型、分区及 Key 标识；更换 Key 后旧生成任务进入待核对，保留服务商任务编号，不会使用新 Key 查询旧任务或自动重新生成。

标签会统一中英文分隔符并去重，连同自动附加的「AI生成」最多十个。投稿失败或结果不明时保留成片，记录具体原因；先在创作中心确认是否已经提交，再按需通过手动投稿处理。

视频模型下拉框同时提供接口返回结果与标注「权限未验证」的已适配选项，列出模型不代表当前 Key 已开通该模型。百炼读取模型时还需填写业务空间 ID，列表使用对应地区的官方业务空间接口；留空仍可直接选择已适配模型进行生成。Key、模型和业务空间按服务及地区独立保存。

自主投稿支持「自动选择投稿分区」：开启后，机器人使用 AstrBot 文本模型，根据选题的镜头描述、标题、简介和标签，从当前 B站账号可用的投稿子分区中选择，并在最近自主投稿记录里显示分区及理由。读取分区失败、模型判断失败或返回无效分区时，沿用你设置的备用分区；关闭后始终使用手动分区。新旧配置默认关闭此开关，已排队任务沿用创建时的开关和备用分区。此功能按生成方案分类，不代表对成片画面的识别或 B站审核结果的保证。

先把视频放入面板显示的素材目录，再到「投稿」选择文件，填写标题、分区等信息并提交。面板可查看投稿状态、实际分区和标签预检结果；投稿成功后可按 BV 号查审核状态（含驳回原因）。分区默认「自动预测」：按标题问 B站，猜不出来才回退到手动分区。AI 声明（「含AI生成内容」）和 4:3 封面默认勾选，可单独关闭；还能填投稿话题（官方活动会自动报名）、定时发布（北京时间，2 小时到 15 天之后）和「仅自己可见」。标签会在提交前预检，B站不收的自动去掉；上传前先要一个上传位，被风控拦截时会说明原因和下一步，而不是只报一个 HTTP 406。

「自主生成并投稿」默认关闭。选择 MiniMax 海螺、火山方舟 Seedance、阿里云百炼通义万相，或「Videos API 兼容（自定义服务）」，再填写 API 地址、Key 和模型。原有三家地址留空时沿用所选地区官方地址，填写地址时按原协议调用；兼容服务必须自行填写地址和模型。设置北京时间和 B站分区后开启并保存。机器人用 AstrBot 的文本模型自主选题，再调用所选服务生成成片，保存到 `media/` 后自动提交。每天有一次定时运行机会，也可点击「立即生成并投稿」，两者共用每日生成上限。Key 按服务和地区分开保存于插件数据目录。填写 Key 后可点击「读取模型」，从服务商返回的已适配文生视频模型中选择。选择结果按服务和地区保存，新任务使用所选模型。切换服务只影响新任务。任务记录会显示成片、BV 号或待核对状态。

自主投稿还可开启「使用文件夹里的三维参考图」。点击「从电脑选择参考图」即可多选本机 PNG/JPG/WebP 三维渲染图或三视图，逐张上传到服务器；关闭浏览器后机器人仍可读取。面板会显示上传结果和图集数量，再勾选参考图开关并保存设置即可使用。重复上传同一名称和内容的图片会复用已有文件，同名但内容不同的图片会分别保存，不覆盖进行中任务的原图。插件自动创建数据目录下的 `reference_images/` 文件夹，也可按面板显示的服务器路径手动传入图片，再点击「刷新图集」。每条新视频都会重新读取图集，按文件名轮换选一张，先发给 AstrBot 识图策划模型，再作为首帧传给视频服务；分别生成时分镜共用该任务的同一张图，连续动作时仅首镜使用原参考图，后续接续上一镜实际尾帧。AstrBot 选用的策划模型需支持图片输入。当前支持海螺 2.3/02、支持图生视频的方舟模型、万相 2.5/2.6；万相会使用对应 `i2v` 模型，其权限和计费以服务商为准。

参考图需为静态图片，单张不超过 10 MB，短边大于 300 像素、长边不超过 4096，宽高比在 2:5～5:2 之间；万相不支持透明通道，可使用不透明 JPG。图片用于首帧参考，不解析 OBJ/FBX/GLB 等三维模型，也不自动把三视图拆成三维角色。开启后，空图集、损坏/被替换的图片或识图失败会阻止相应生成，不会自动退回文字生成。同一任务固定参考图内容，分镜中途换图须恢复原图后再重试；新增或替换图集会供后续任务重新读取。原始参考图不会随投稿后的成片清理而删除，图片本身不会写入 Git、公开地址或任务账本。该开关默认关闭，旧任务和旧设置保持兼容。

「配音与字幕」仍在「投稿」页的独立折叠栏目，默认关闭。新模式可选「角色声画同步 · 模型原生生成」或「保留原声 · 仅识别字幕」。设置只影响新任务，已有任务保留原方式；旧版旁白任务和配置兼容，不会自动改写已生成声音。

角色模式由 AstrBot 为单段或各分镜安排最多三句有明确说话人和大致时间窗的台词，也允许没有对白的镜头。台词、声音风格与嘴形同步要求一起传给支持的原生有声视频模型，方舟明确启用 `generate_audio`，万相 2.5/2.6 使用其有声生成能力；参考图及连续镜头尾帧仍按原流程传入。不克隆音色，不另加 TTS 旁白，角色身份、音色一致性与口型精度仍由模型决定。当前海螺和无法判断底层能力的方舟 endpoint 不声明原生声音支持，界面会提示切换支持的模型；若实际成片无声则直接保留。参考：[方舟任务 API](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)、[方舟提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-0-prompt-guide?lang=zh)、[万相有声生成说明](https://help.aliyun.com/en/model-studio/text-to-video-guide)。

开启「将字幕显示在画面中」后，插件从最终单段或合成成片提取实际音轨，按所选识别协议调用 Paraformer 兼容 WebSocket 服务，或 OpenAI/Whisper 兼容 HTTP 服务，并据实际返回的分段起止时间生成 SRT/ASS、烧录字幕。只采用最终识别结果，忽略中间稿和心跳；缺少有效时间戳则暂停处理，不用计划台词兜底。字幕是原声文字转写，未增加跨语言翻译；字幕绘制保持白字深色描边、底部居中，字号以720p为基准。新模式保留原音轨，不叠加或替换为旁白。参考：[识别协议](https://help.aliyun.com/en/model-studio/websocket-for-paraformer-real-time-service)、[识别时间戳](https://help.aliyun.com/en/model-studio/paraformer-server-events)。

识别可选择「百炼 / Paraformer 兼容」或「OpenAI / Whisper 兼容」，分别填写 API 地址、Key 和模型 ID。Paraformer 默认连接百炼北京地区，业务空间 ID 可选；自定义 WebSocket 地址优先生效。HTTP 兼容服务调用 `/audio/transcriptions`，以 WAV 上传并要求 `verbose_json` 和 `segments` 时间戳，仅返回纯文本的模型不适用同步字幕。各识别协议单独保存地址、模型和 Key，切换时清空 Key 输入草稿，空 Key 输入沿用该协议此前保存的 Key；清除只影响当前识别服务。旧百炼 Key 在读取时兼容、保存时迁入私有 `asr_profiles`，不自动复制视频或旧配音 Key。识别服务按提供方规则计费。关闭字幕时不调用识别服务；没有识别到说话内容则保留原声、不添加字幕，不把环境声和音乐虚构为角色台词。只有无声时，才会连识别也跳过。

无声判断同时覆盖没有音轨和分镜合成插入的静音音轨，检查实际解码采样，约低于 -72 dBFS 的数字残留视为静音。无声成片不生成配音、字幕或重新编码，面板显示「无声视频 · 已跳过配音与字幕」。解码失败时保留视频并暂停，不把无法读取误认为无声。

识别请求前持久化任务编号及 requesting 状态；断线、异常或重启后不自动重新计费识别，任务保留为可重试的后期失败。手动「重试后期处理」会重新提交未完成的识别，可能再次计费；已完成识别后的烧录失败只复用识别结果本地重合成，不再提交识别，不需要保留识别 Key。可在明确手动重试时采用任务原识别协议新保存的 Key、地址、模型和业务空间；进行中的任务不会因切换设置而自动改投其他接口。识别或字幕失败不跳过处理直接投稿。原视频备份及字幕按文件身份保护，在 B站确认正常后与成片一起清理；参考图不受影响。

服务器需要 `ffmpeg`、`ffprobe`、libass（`ass`/`subtitles` 滤镜）和中文字幕字体，可安装文泉驿微米黑或 Noto CJK，或在数据目录 `fonts/wqy-microhei.ttc` 放入授权字体。独立配置为数据目录 `voiceover_settings.json`，不纳入 Git。旧版 MiniMax/千问 TTS 仅用于兼容此前已开启或已排队的旁白任务，新角色模式不依赖训练 TTS，也不使用这些预设音色覆盖角色原声。


视频接口的自定义 Base URL 包含 API 前缀（例如 `https://你的服务/v1`），不在地址里附带 Key。可从 `/models` 读取模型，或在「手动填写视频模型 ID」中输入平台给出的 ID。自定义服务的列表未必标注视频能力，模型出现不代表视频权限已验证。原生协议需要服务端兼容海螺/方舟/万相相应创建、查询和下载格式；填写其他平台地址不会自动转换任意 API。

「Videos API 兼容」支持 `POST /videos` 创建、`GET /videos/{id}` 查询（queued/in_progress/completed/failed）、`GET /videos/{id}/content` 鉴权下载；请求可选 multipart 或 JSON。参数使用 model、prompt、seconds、size，参考图会转成1280×720后以文件或input_reference对象上传；返回字段必须兼容上述协议。默认协议时长为4/8/10/12秒，单段可选；分镜60秒可用5×12秒，30秒可用12+10+8三段（10秒只对能接受它的服务开放，本机 H3 桥接支持）。兼容模型支持原生声音时可按服务商说明勾选能力，再使用角色模式；该勾选不代表插件已实测模型。参考：[接口格式](https://developers.openai.com/api/reference/resources/videos/methods/create)、[音轨识别格式](https://developers.openai.com/api/reference/resources/audio/subresources/transcriptions/methods/create)。官方文档已标注Videos API于2026-09-24下线，此入口面向自行配置的兼容服务，不预置官方视频地址，也不保证某一模型仍可用；[官方下线说明](https://developers.openai.com/api/docs/deprecations)。

新视频任务固定创建时的地址、模型和请求格式，后续编辑服务地址不影响旧任务查询和下载；Key更换仍按原指纹保护。识别任务同样固定协议/地址/模型，只有明确手动重试未完成识别才采用任务同协议的新配置。原有 Key、图片、任务和默认服务在升级时保留。兼容接口改动不触发生成或识别，实际计费在用户开启并运行后按服务商规则发生。

## 本机 ComfyUI 生成视频

`tools/comfyui_bridge.py` 将 MiniMax H3 多参工作流接到投稿页的「Videos API 兼容（自定义服务）」。桥接程序需要 Python 3.11 及以上、`aiohttp`、`Pillow`，以及同一台电脑上的 ComfyUI、H3 Ref2VA 权重和对应的 4 步加速 LoRA。它提交工作流、查询指定任务并读取成片。[ComfyUI 接口文档](https://docs.comfy.org/development/comfyui-server/comms_routes)

在桥接状态目录放置包含 64 位随机十六进制字符的 `bridge.key`，然后运行 `python tools/comfyui_bridge.py --state-dir <状态目录>`。桥接监听本机 `127.0.0.1:18188`，ComfyUI 默认使用 `127.0.0.1:8188`。桥接按 ComfyUI 检测到的显存容量和视频时长选择竖屏分辨率，也可同时传入 `--width` 和 `--height` 手动指定。AstrBot 在远端时，需要用私有隧道转发桥接端口。

在投稿页填入 AstrBot 能访问的桥接地址（以 `/v1` 结尾）和对应的桥接鉴权令牌，使用 `multipart` 格式和模型 `comfyui-h3`，并关闭原生声音。该预设输出没有音轨的 24 fps MP4。需要 H3 原生声音时，可选择 `comfyui-h3-audio` 并开启原生声音。实际时长会按模型要求的帧数取整。开启投稿页的参考图选项后，图集中的图像通过 `<Picture 1>` 参与角色外观参考，视频从生成的场景起镜。

电脑、ComfyUI 和桥接进程需保持运行。桥接保存任务编号映射，ComfyUI 中的原任务记录仍存在时，可继续查询原任务。桥接令牌用于本地服务鉴权，生成使用本机 GPU。

## QQ 读取 B站分享卡片

私聊直接发送 B站视频卡片，机器人会自动读取真实标题、UP主、简介和可用字幕，再通过当前 AstrBot 聊天模型、人设和会话回复简要内容；带具体问题时优先回答问题。群聊需满足已有的 @ / 唤醒规则，不因无关卡片或普通消息唤醒。支持常见 QQ 小程序 JSON 卡片、分享卡片、旧式 XML/CQ 卡片、完整 BV 视频链接和 `b23.tv` 短链；动态、直播、文章等非视频卡片暂不处理。

这项读取不等于观看视频画面：字幕最多读取前 5000 字符，超长时会标明截断；无字幕或字幕读取失败时，仅依据简介说明，材料不足则不猜视频内容。卡片内的标题不直接当成视频事实，简介/字幕中的指令不作为操作要求，也不自动触发自主学习、评论、互动或投稿。仍需服务器可访问 B站，并沿用现有登录与风控暂停。

同一视频资料短暂缓存 5 分钟，单次处理最多 25 秒；同一会话的同一发送者每 10 秒处理一条，同一消息 ID 在 2 分钟内判重。短链最多三次跳转，只请求受支持的 B站地址，不跟随外站/内网跳转。读取失败会回复简洁原因，不让聊天模型凭空概括。只保存当前会话中的读取材料，不另建长期卡片数据库。

## 自主学习与创作经验

「投稿 → 自主学习」默认关闭，开关同时控制新学习和新策划的经验引用。在正常刷视频挑中内容后，插件检查平台 AI 生成声明或作者明确声明整段视频画面由 AI 生成；仅出现 AI 标题、标签、含糊或冲突信息均不学习，不补扫历史视频。声明只是保守准入依据，无法保证视频确实由 AI 生成。

开启后需当前 AstrBot 模型支持多图识别，服务器需有 FFmpeg/ffprobe。每天最多尝试 1～3 条（默认 2 条，北京时间），每条抽取 4 或 6 张关键帧（默认 4 张）；第一版只分析单 P、2～120 秒、下载不超过 40 MB 的视频，不分析音频。临时视频和关键帧在结束后清除，只保存来源、声明、采样时间和至多三条待验证经验。失败、中断也占当天额度，同一视频不自动重试；没有明确声明时不下载、不调用学习模型。

单段和分镜策划完成后，按题材匹配至多五条经验，总经验上下文不超过 1200 字符，再进行一次文本优化。只调整镜头描述，保留标题、台词、时长和结构；无相关经验、开关关闭或优化失败时沿用原策划，不追加视频生成请求。实际采用的经验快照可在最近自主投稿记录中查看。已有任务不因经验删除、反馈或关闭开关而改变。

少量关键帧不能完整判断快速动作、节奏和口型同步，也不能还原作者的真实提示词。经验是可迁移的制作推断，不训练海螺等视频模型，不保证成片效果。可按实际结果将经验标记为「有帮助」「不适用」或「待验证」；不适用的经验不再引用。删除学习记录会删除其中经验，但保留判重和当天用量。最多保留最近 100 条记录；独立判重最多 5000 条，达到后停止新增学习并在面板提示。数据在插件目录的 `creative_learning.json`，不纳入 Git。

## 开发与维护

从 [dsh-bili-scroll 2.0](https://github.com/c1overzz/dsh-bili-scroll)（MIT）移植，B站工具层基于上游的 bilibili-mcp。

- `main.py`：插件入口、面板接口和聊天工具。
- `duty.py`：搜索、去重、读取内容、筛选、评论与日报流程。
- `rhythm.py`：时间窗口与随机唤醒计划。
- `reply.py`：回复处理和待审草稿。
